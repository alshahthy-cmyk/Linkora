# عقد Linkora للإشارات والحالات الفورية

## أهداف الإصدار

يحافظ خادم الإشارة على مهمته الأساسية: توجيه رسائل صغيرة بين جهازين متصلين فقط، من دون تخزين الرسائل أو الملفات. تضاف حالات الرسائل والحضور والكتابة وإشارات WebRTC ضمن `payload` الممرر من الخادم؛ ولا يحتاج الخادم إلى فهم محتواها إلا للتحقق من الحجم والوجهة.

## نموذج المحادثة المحلي

كل محادثة تحفظ الحقول التالية محلياً على الجهاز:

| الحقل | المعنى |
|---|---|
| `isOnline` | الجهاز الآخر متصل حالياً بخادم الإشارة. |
| `lastSeenAt` | آخر وقت معروف لانفصال الجهاز الآخر. |
| `isTyping` | مؤشر مؤقت، يعاد إخفاؤه تلقائياً بعد 4 ثوانٍ. |
| `messages[].status` | `sending` ثم `sent` ثم `delivered` ثم `read`. |
| `messages[].replyTo` | تعريف الرسالة الأصلية ومعاينة قصيرة منها. |
| `messages[].deletedAt` | وقت الحذف المحلي أو البعيد؛ عند وجوده لا يعرض المحتوى. |

## أحداث الرسائل

| `payload.type` | المرسل | الغرض |
|---|---|---|
| `message` | المرسل | رسالة نصية أو وسائط؛ يجب ألا تتجاوز بياناتها المشفرة 8 ميغابايت. |
| `message-received` | المستقبل | تأكيد وصول الرسالة إلى التطبيق؛ ينقل حالة المرسل إلى `delivered`. |
| `message-read` | المستقبل | تأكيد قراءة الرسالة؛ ينقل حالة المرسل إلى `read`. |
| `message-delete` | صاحب الرسالة | حذف الرسالة من شاشة الطرفين. |
| `typing` | كاتب الرسالة | قيمة منطقية لإظهار أو إخفاء «يكتب الآن». |
| `presence` | الخادم | إشعار اتصال/انفصال مع آخر وقت ظهور. |

## مرفقات الإصدار التجريبي

هذه النسخة تنقل المرفقات مباشرة بين الطرفين عبر خادم الإشارة، ولذلك تفرض الحد التالي لتجنب تعطل الاتصال أو استهلاك ذاكرة الهاتف:

| نوع المرفق | الحد الأقصى | العرض في المحادثة |
|---|---:|---|
| صورة | 5 ميغابايت | معاينة داخل المحادثة وفتح بالحجم الكامل. |
| فيديو | 8 ميغابايت | بطاقة فيديو مع زر تشغيل داخل المحادثة. |
| ملف أو رسالة صوتية | 8 ميغابايت | بطاقة باسم الملف والحجم وزر فتح/تشغيل. |

الإصدار العام واسع النطاق يحتاج نقل المرفقات إلى تخزين ملفات مستقل وموقّع، لا إلى رسائل WebSocket، قبل إزالة هذه الحدود.

## أحداث المكالمات

تستخدم المكالمات `react-native-webrtc` وتبقى إشارات التفاوض داخل WebSocket الحالي. يضاف إلى كل حدث `callId` عشوائي لمنع خلط مكالمتين متزامنتين.

| `payload.type` | الوصف |
|---|---|
| `call-request` | دعوة تتضمن `callId` و`mode` (`audio` أو `video`). |
| `call-accept` | قبول الدعوة. |
| `call-reject` | رفض الدعوة أو عدم توفر الأذونات. |
| `webrtc-offer` | وصف جلسة العرض SDP. |
| `webrtc-answer` | وصف جلسة الإجابة SDP. |
| `webrtc-ice` | مرشح ICE واحد. |
| `call-end` | إنهاء المكالمة وتنظيف مسارات الوسائط. |

## موثوقية المكالمة

يمكن لـ STUN إنشاء اتصال مباشر في كثير من الشبكات، لكنه لا يكفي لكل شبكات الهاتف أو شبكات الشركات. لذلك سيستخدم العميل STUN عاماً للتجربة، ويُترك متغير `EXPO_PUBLIC_TURN_URL` لعنوان TURN مصادق عليه قبل الإطلاق العام. لا توضع بيانات اعتماد TURN الدائمة داخل مستودع عام أو داخل التطبيق النهائي؛ يجب إصدارها مؤقتاً من خدمة آمنة في النسخة الإنتاجية.

## توافق Expo وWebRTC

يربط مشروع Linkora بـ Expo SDK 54. توثيق `@config-plugins/react-native-webrtc` يحدد لهذه النسخة التوافق التالي: `react-native-webrtc@124.0.6` و`@config-plugins/react-native-webrtc@13.0.0`. المكتبة تتضمن شفرة أصلية، ولذلك لا تعمل في Expo Go، لكنها تعمل ضمن تطبيق Android مبني عبر EAS بعد إضافة الإضافة إلى `app.json` وإعادة البناء.
